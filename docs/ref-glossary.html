▶A. 規格・全体Standards12 語
用語
意味
詳しくは
PKCS
Public-Key Cryptography Standards
RSA 社（RSA Laboratories）がまとめた公開鍵暗号の標準の一群。#11 はその11番目
—
PKCS#11
—
暗号デバイス（HSM・IC カードなど）を操作する C 言語の API の標準。このサイトの主題
第0章
Cryptoki
Cryptographic Token Interface
PKCS#11 の API の名前。関数名の C_ や型名の CK_ はここから来ている
第0章
OASIS
Organization for the Advancement of Structured Information Standards
いま PKCS#11 の仕様を作っている標準化団体。PKCS 11 TC（技術委員会）が版を出す
—
v2.40・v3.0・v3.2
仕様の版
v2.40 は OASIS 版の最初の基準（関数 68）。v3.0 で 24 加わって 92、v3.2 で 12 加わって 104
関数
HSM
Hardware Security Module
鍵を中にしまい、暗号の計算も中で行う専用の装置。鍵の値を外に出さないのが役目
第0章
Cryptoki ライブラリ
.so / .dll
HSM のベンダーが配る、PKCS#11 の関数の実体。アプリはこれを読み込んで呼ぶ
第0章第1章
API
Application Programming Interface
プログラムから機能を呼ぶための約束ごと
—
FFI
Foreign Function Interface
ほかの言語（C）の関数を Rust から呼ぶしくみ。cryptoki は中で使っている。包みのない関数は FFI で直接呼ぶ
第1章関数
ABI
Application Binary Interface
関数の呼び方や構造体の並び方など、バイナリの約束ごと。関数の表の並び順もこれで決まる
第1章
cryptoki
Rust のクレート
このサイトのサンプルが使う、Rust の PKCS#11 ラッパー（0.12）。関数を安全なメソッドに包んでいる
第0章関数
トークン次第

用語
意味
詳しくは
スロット
Slot
トークンを差す口。番号は固定とは限らないので、トークンはラベルで探す
第2章
トークン
Token
鍵などのオブジェクトを持ち、暗号の計算を行う実体。HSM の中の区画などに当たる
第0章第2章

CK_FUNCTION_LIST
C_GetFunctionList が返す、関数ポインタの並び。v2.40 は 68 個。このあとの関数はすべてここから呼ぶ
第1章
3つの初期化
C_Initialize / C_InitToken / C_InitPIN
ライブラリを使い始める・トークンを用意する（中身は消える）・SO が User PIN を決める。対象もタイミングも違う
第1章
セッション
Session
アプリとトークンをつなぐ通り道。操作はすべてセッションの上で行う。トークンごとに開く
第2章シナリオ1
R/O・R/W
Read-Only / Read-Write
読むだけのセッションと、トークンに残る変更もできるセッション。鍵を使うだけなら R/O で足りる
第2章
セッションの状態
CKS_*
R/O か R/W かと、だれがログインしているかの組み合わせで5つ（RoPublic・RoUser・RwPublic・RwUser・RwSecurityOfficer）
第2章
ログイン
C_Login
トークンに対して1回。同じアプリのそのトークンのセッションすべてに効き、最後のセッションを閉じるか C_Logout するまで続く
第2章シナリオ1
SO
Security Officer
トークンの管理者。User PIN を決める（C_InitPIN）。鍵の利用者ではない
第1章
User
CKU_USER
鍵の利用者。ログインすると、非公開のオブジェクトを作ったり使ったりできる
第1章第2章
PIN
Personal Identification Number
ログインに使う暗証番号。SO PIN と User PIN がある。何回間違えるとロックされるかはトークン次第
第1章メンテナンス API

Random Number Generator
乱数生成器。C_GenerateRandom が使う。トークンが持っていれば CKF_RNG が立つ
第2章第7章
HW / FW
Hardware / Firmware
スロットやトークンのハードウェア・ファームウェアの版。C_GetSlotInfo・C_GetTokenInfo で読める

▶F. 暗号アルゴリズムAlgorithms17 語
用語
意味
詳しくは
共通鍵暗号・公開鍵暗号
対称 / 非対称
同じ鍵で暗号化と復号をするもの／公開鍵と秘密鍵の組を使うもの
第4章第6章
RSA
Rivest–Shamir–Adleman
公開鍵暗号。署名と暗号化に使う。強さは法の長さ（ビット）
第4章第6章第7章
EC・ECC
Elliptic Curve (Cryptography)
楕円曲線暗号。短い鍵で強い。強さは曲線（P-256 など）で決める
第4章第7章
ECDSA
Elliptic Curve Digital Signature Algorithm
EC の鍵での署名。CKM_ECDSA はハッシュを含まないので、先にハッシュして渡す
第7章
EdDSA・Ed25519
Edwards-curve DSA
Edwards 曲線での署名。Ed25519 は Curve25519 を使うもの。v3.0 のメカニズム
メカニズム
ECDH
Elliptic Curve Diffie–Hellman
2者がそれぞれの鍵ペアから同じ共通鍵を得る鍵共有（C_DeriveKey）
関数メカニズム
X25519
—
Curve25519 での鍵共有。このサイトでは扱っていない
—
DSA・DH
Digital Signature Algorithm / Diffie–Hellman
古い署名方式と鍵共有。強さは素数 p の長さ（ビット）
メカニズム
AES
Advanced Encryption Standard
共通鍵暗号の標準。鍵は 16 / 24 / 32 バイト、ブロックは 16 バイト
第4章第6章
DES・3DES
Data Encryption Standard
古い共通鍵暗号。単一 DES は短すぎて破れる。3DES も新しくは使わない
第4章第6章
ハッシュ
SHA-1・SHA-256 など
データを決まった長さに要約する。鍵は使わない（C_Digest）
第7章
SHA
Secure Hash Algorithm
ハッシュの規格。SHA-256 は 32 バイト
第7章
署名・検証
Sign / Verify
秘密鍵で作り、公開鍵で確かめる
第7章
MAC
Message Authentication Code
共通鍵で作る改ざん検知の値。作るのも確かめるのも同じ鍵
第7章
HMAC
Hash-based MAC
ハッシュを使う MAC。鍵は汎用の共通鍵（CKK_GENERIC_SECRET）
第4章第7章
CMAC
Cipher-based MAC
ブロック暗号（AES など）を使う MAC
メカニズム
ML-KEM・ML-DSA
FIPS 203 / FIPS 204
耐量子暗号の鍵カプセル化と署名。v3.2 で加わった（C_EncapsulateKey など）

▶G. 暗号のモード・パラメータModes and parameters16 語
用語
意味
詳しくは
IV
Initialization Vector
CBC や GCM に渡す初期値。毎回変える。秘密ではない
第6章
nonce
Number used once
一度だけ使う値。GCM の IV はこれに当たる
第6章
ECB
Electronic Codebook
ブロックごとに独立に暗号化する。模様が残るので、データには使わない
第6章
CBC
Cipher Block Chaining
前のブロックとつないで暗号化する。IV が要る。改ざんには気づかない
第6章
CTR
Counter
カウンタを暗号化して平文に XOR する。埋めない。改ざんには気づかない
第6章
GCM
Galois/Counter Mode
暗号化と改ざん検知を同時に行う（AEAD）。タグを付ける
第6章
AEAD
Authenticated Encryption with Associated Data
認証つき暗号。暗号化しない付随データ（ヘッダなど）の改ざんも見つける
第6章
タグ
Tag
GCM などが暗号文に付ける改ざん検知の値（16 バイト）
第6章
パディング
Padding
ブロックの長さにそろえる詰め物
第6章
PKCS#1 v1.5・PKCS#7
—
RSA の古い詰め方（暗号化・署名）と、ブロック暗号の詰め方（CBC_PAD）
第6章第7章
OAEP
Optimal Asymmetric Encryption Padding
RSA 暗号の詰め方。新しく使うならこちら
第6章
PSS
Probabilistic Signature Scheme
RSA 署名の詰め方
メカニズム
KDF
Key Derivation Function
共有した秘密から鍵を導く関数（ECDH の後段など）
関数
KEK
Key Encryption Key
鍵を包むための鍵
シナリオ1シナリオ2

データを暗号化する鍵。KEK で包んで持つ
シナリオ2
AES Key Wrap
RFC 3394 / RFC 5649
AES で鍵を包む方式（CKM_AES_KEY_WRAP / _PAD）。包みの正しさも検査する
