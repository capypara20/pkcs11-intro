コマンドリファレンス（pkcs11-tool・softhsm2-util）

トークンの用意・状態の確認・鍵の出し入れ・PIN の管理・バックアップを、コマンドで行うときの引き表（26 件）。すべて CI で実行し、中で呼ばれる PKCS#11 の関数も記録して確かめている。同じ作業を API で行うときはメンテナンス API リファレンスへ。

使う道具

コマンドどこで使えるか中身
pkcs11-toolどの HSM でも（--module でライブラリを指定）OpenSC に入っている。PKCS#11 の関数を呼ぶだけなので、HSM の種類を問わない
softhsm2-utilSoftHSM2 だけトークンの作成・削除と、鍵ファイルの取り込み
openssl（確認用）書き出した公開鍵や署名を、HSM の外で確かめる

本物の HSM には、ベンダーの管理ツールがある（トークンの初期化・バックアップ・複製・監査ログなど）。それらは PKCS#11 の外の仕組みで、このページでは扱わない。

「中で呼ばれる関数」の調べ方

OpenSC の pkcs11-spy を間にはさむと、呼ばれた関数と引数をすべて記録できる。本物のライブラリは環境変数 PKCS11SPY で渡す。

PKCS11SPY=/usr/lib/softhsm/libsofthsm2.so \
PKCS11SPY_OUTPUT=spy.log \
pkcs11-tool --module /usr/lib/x86_64-linux-gnu/pkcs11-spy.so -L

表には、そのコマンドの本題の関数だけを載せた（C_Initialize・C_OpenSession などの決まった前後の呼び出しは省いた）。cryptoki のサンプルも同じ方法で記録できる（PKCS11_MODULE に spy を渡す）。

PIN をコマンドラインに書くこと

このページでは確かめやすさのために --pin に PIN を直接書いている。実際の運用では、シェルの履歴や ps に残るので書かない。--pin を省けば、pkcs11-tool がその場で聞いてくる。

▶C. 鍵を作る・入れる・出す6 件
指定しなかった属性はトークンの既定になる。SoftHSM2 で --keygen した AES 鍵は、用途を何も指定しなくても、暗号化・署名・包むなどすべての用途が TRUE だった。用途を絞るなら、作る側で明示する（第4章）。
EC 鍵ペアを作る
どの HSM でも

C_GenerateKeyPair で P-256 の鍵ペアを作り、公開鍵と秘密鍵に同じ CKA_ID（01）とラベルを付ける（第5章）。

pkcs11-tool --module /usr/lib/softhsm/libsofthsm2.so \
    --token-label maint --login --pin 1111 --keypairgen --key-type EC:prime256v1 --id 01 --label orders-sign --usage-sign
--key-type は rsa:2048、EC:ed25519 なども書ける。
中で呼ばれる関数

    --token-label maint --login --pin 1111 --keygen --key-type AES:32 --id 02 --label orders-data --sensitive
値を読もうとして CKR_ATTRIBUTE_SENSITIVE の警告が出るのは正常（読めないのが正しい）。

署名する
どの HSM でも

ハッシュ済みの値に CKM_ECDSA で署名し、openssl が読める DER 形式で書き出す（既定は r‖s、第7章）。

    --token-label maint --login --pin 1111 --sign -m ECDSA --id 01 -i h.bin -o sig.der --signature-format openssl
SoftHSM2 には ECDSA-SHA256 がないので、先に --hash でハッシュしてから署名する。

CKA_ID を付け替える（秘密鍵）
どの HSM でも

C_SetAttributeValue で、ID が 01 の秘密鍵の CKA_ID を 11 にする。

変わるのは指定した1つだけ。公開鍵は 01 のままなので、このままでは --id 11 で検証しようとしても公開鍵が見つからない（確認済）。

どの HSM でも

PIN を何度も間違えると、トークンのフラグに「user PIN count low」が立つ。

pkcs11-tool --module …/libsofthsm2.so -L   # PIN を何度も間違えたあと
SoftHSM2 は 12 回間違えてもロックしなかった。本物の HSM の多くは、決まった回数でロックする（user PIN locked）。

SoftHSM2 だけ

使っていないときに tokendir を写しておけば、消えても戻せる。戻したトークンは鍵も PIN も元のまま。
